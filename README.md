# 敘獎 CSV 產製工具

讀取教育局敘獎公文 PDF，比對校內人員基本資料，產出 WebHR 獎懲作業（CPAA0118B）匯入用的 CSV。

純前端網頁，沒有後端。上傳的人事資料與公文只留在瀏覽器記憶體，關掉分頁就沒了，不會送到任何伺服器。

## 對外連線

平常只有一個地方會對外發出請求：頁尾的到訪計數。

另外有個**選用**功能會連外：設定了 Mac 端 OCR 之後，遇到掃描件時會把 PDF 送到你自己架的服務辨識。沒設定就完全不會用到。詳見下方「Mac 端 OCR」。

送出的內容只有一個固定的計數 key（`ctsai0124.github.io/webhr-award-csv`），**不含任何人事資料、檔名或解析結果**。對方看得到的是「有人開了這個頁面」加上你的 IP，僅此而已。

用的是 [Abacus](https://abacus.jasoncameron.dev)，免註冊、免金鑰，計數器不會被公開列出。服務掛掉、被防火牆擋或離線使用時會靜靜略過，不影響任何功能。

**不想要就把 `ui.js` 開頭的 `VISIT_KEY` 設成空字串**，之後這個網頁完全不會連外。若學校對外部連線有規範，建議直接關掉。

## 部署到 GitHub Pages

1. 建一個 repo，把這幾個檔案放進去
2. Settings → Pages → Source 選 `main` 分支的根目錄
3. 開 `https://<帳號>.github.io/<repo>/`

也可以直接下載整包，用瀏覽器打開 `index.html` 就能用。

## 使用流程

**機關代碼會自動帶入。** 名冊表頭有學校名稱，程式會查內建的高雄市學校代碼表（345 所）自動填好，不用自己記十位數的代碼。名冊寫簡稱（三侯國小）也查得到，但只在唯一相符時才採用。查不到的仍可手動輸入。

**1. 上傳人員基本資料表（CPAB1207R）**
從 WebHR「個人資料 › 個人基本資料 › 報表 › 職員名冊」下載，提供身分證號與職稱。下載前請先排除不需由學校辦理敘獎的人員，例如校長；名冊上沒有的人不會出現在結果裡。

也可以另外上傳歷年獎懲明細表（CPAB1209R），系統會拿裡面的事由當語料，撰寫新事由時列出相似寫法供你一鍵套用。

**2. 上傳敘獎公文 PDF**
可以一次選多份。正常電子公文直接讀取 PDF 文字層；整份文件偵測不到足夠文字時，會在瀏覽器內啟動繁體中文 OCR。OCR 結果一律標示需人工確認，不會預設核章。

**3. 核對**
每筆左側有個「核」章，蓋了才會寫進 CSV。姓名、獎度、事由都能直接改。

上傳完成後會逐份列出敘獎人數與資料筆數，例如「1 人（2 筆）」表示同一人因不同分工有兩筆敘獎。

匯出區會列出本次核章的獎度分布（嘉獎一次 N 筆、記功一次 N 筆、來自幾份公文），送進 WebHR 前可以先對一次額度。

頁尾顯示版本號、到訪次數與累計數字。累計只存在這台電腦的瀏覽器裡（`localStorage`），不會外傳，記錄總共匯出過幾筆、幾份公文、幾次，可以隨時歸零。無痕模式或瀏覽器擋住儲存時會自動略過，不影響其他功能。

**4. 匯出**
產生 Big5 CSV，到 WebHR：獎懲作業 › 一般獎懲 › 獎懲案件維護作業 → 建立令(稿) → 明細 → 匯入 CSV。

## 解析怎麼運作

**只讀「擬辦」段落。** 公文後半的批核軌跡會列出校長、人事主任等所有簽核者，那些人不是受獎人。程式會從「擬辦：」或電子公文的「意見及流程／文號」開始擷取，遇到「批核軌跡」「批示」就停。

**以人員名冊為錨點找姓名**，而不是猜姓名長什麼樣。三種比對強度：

| 標記 | 意思 | 例 |
|---|---|---|
| 姓名相符 | 完全一致 | 林怡慈 |
| 疑似錯字 | 同姓、差一個字 | 公文寫「江雨薇」→ 名冊是江宇薇 |
| 需確認 | 只有名沒有姓 | 公文寫「怡慈老師」→ 林怡慈 |
| 姓＋職稱 | 單位＋姓＋職稱都吻合且唯一 | 公文寫「學務曾主任」→ 學務處姓曾的主任，自動核章 |
| 職稱對應 | 只有職稱，連姓都沒有 | 公文寫「教學組長」→ 名冊上的教學組長 |
| 多人符合 | 推定後不只一個人符合 | 下拉會把候選標上 ◆ 排在最前面 |

職稱推定要求「姓必須真的是名冊上某人的姓」，所以「訓導組長」不會被誤讀成姓「導」。單位條件會先套用，找不到人才放寬成只看姓和職稱。學務處和訓導處視為同一單位。

只有「姓名相符」且獎度明確的才會預設蓋章，其餘要你自己確認。

**獎度寫法支援「次」「支」「個」和「乙次」**，「嘉一次」這種漏字也認得。「各嘉獎1支」「均記功1次」會被判定為共用獎度，套用給**同一個句段裡列出的每個人**，而不是只給最後一位。範圍會限縮在句號、分號、換行和「1.」「一、」這類條列編號之間，避免外溢到不相干的名單——例如「相關行政人員各嘉獎1次(至多5人)。…3.教導主任，教學組長，訓導組長各嘉獎1次」，前一句沒列人所以不會亂配。

**「嘉獎2次1人：甲主任、嘉獎1次3人：乙老師、丙主任」這種標題式寫法**也認得。獎度寫在前面當標題，一路管到下一個獎度出現為止，中間列的人全部適用。

**競賽類公文的區別詞會優先辨識。** 同一位老師帶兩個班或兩個項目時，差別通常在班級（三年甲班）、組別（低年級組）、名次（優等、第一名）或科目，這些會優先被抓來當區別詞。

**公文層級的警告不會連坐。** 警告分成兩種：動搖整份配對可信度的（PDF 含多組主旨、OCR 辨識、姓名數與獎度數對不上、來文有多種獎度），整份都不自動核章；只描述個別列狀況的（某個職稱多人符合、某人事由撞號），只影響那幾列，同一份公文裡其他已經確定的人照樣核章。

擬辦沒寫獎度而改用來文本文的獎度時，有兩種情況視為明確、不阻擋核章：

1. **全文只出現一種獎度** —— 套用給誰都不會錯
2. **依本校成績等第查到的** —— 評鑑類公文擬辦常只寫「本校成績為優等」，獎度另列在來文規則裡，程式會照等第去對，這是精準結果，即使來文列了特優／優等／甲等三種也不算不確定

只有真的查不出本校適用哪一種時才會擋，而且提示會把來文有哪幾種獎度列出來，方便你從下拉挑。

**同一人多筆時事由會自動寫成不同的。** WebHR 不接受同一人有獎懲類別、事由、核定日期完全相同的兩筆，所以事由撞在一起就匯不進去。分工（承辦／協辦）和範圍（一忠導師、國語）都辨識不出來時，程式會從擬辦裡各筆所在的句段抓出區別詞，放進括號：

```
擬辦：1.協助辦理數位學園教師研習：秦桂屏、李雲菁各嘉獎1次。
      2.協助辦理數位學園成果展示：秦桂屏嘉獎1次。

秦桂屏  協助辦理114年度「高雄數位學園」推廣計畫（教師研習），辛勞得力
秦桂屏  協助辦理114年度「高雄數位學園」推廣計畫（成果展示），辛勞得力
```

描述寫在姓名前（冒號分組）或姓名後（「秦桂屏辦理線上課程建置嘉獎1次」）都抓得到，事由裡已經講過的字會被砍掉避免重複。真的抓不出差異時才標黃請你自行補上，那筆也不會預設核章。

**同一人可以在同一份公文出現多筆。** 這通常代表同一人因不同工作或事由分別敘獎，例如主辦、承辦、協辦，不同班級、科目、測驗或負責範圍。系統會保留每一次明確姓名，不再依身分證號合併；事由會依分工或範圍改成不同寫法。只要各筆範圍都能辨識，就視為正常資料；只有產生的事由可能完全相同時才標示提醒並取消預設核章。只有職稱推定出的同一人不會因此重複新增，避免把「姓名旁的職稱描述」誤認成另一筆敘獎。

判定標題的分隔號只收冒號和破折號，不收頓號逗號 —— 否則「…敘嘉獎2次、林怡慈老師…」會被誤判成標題，把下一個人的獎度吃掉。

**獎度配對用四階段。** 依序是標題式獎度、共用獎度（各／均）、一般配對、反方向補找。一般公文多是「姓名在前、獎度在後」，表格式擬辦則常是「獎度在前、姓名在後」；程式會先比較整段的排列方向再認領，每個個別獎度只能被一個人拿走。

單純取最近距離會出錯 —— 名單連寫時，後一個人的姓名離前一個人的獎度反而更近。例如「侯進昇主任…敘嘉獎2次、吳靜琪幹事…敘嘉獎1次」，吳靜琪離侯進昇的獎度只有 5 個字，離自己的有 12 個字。

同一句若先寫個別獎度、後寫共用獎度，例如「蘇宇祥教師嘉獎2次，教導主任、總務主任各嘉獎1次」，後面的「各嘉獎1次」只套用到前一個獎度之後列出的人，不會回頭覆蓋蘇宇祥。

**整份公文的可信度會被評估。** 姓名數和獎度數對不起來，通常表示 PDF 表格在抽文字時被打亂了，這時整份會標記為需人工核對，不預設蓋章。

## 法規欄位對應

| 人員類別 | 適用法規 | 嘉獎 | 記功 |
|---|---|---|---|
| 教育人員（教師） | CA 公立高級中等以下學校教師成績考核辦法 | 第6條第2項第3款第10目 | 第6條第2項第2款第9目 |
| 公務人員 | 預設留空，於 WebHR 確認 | 預設留空 | 預設留空 |

教師嘉獎固定以「第6條第2項第3款」判斷，無法再細分時一律採第10目「其他辦理有關教育工作，成績優良」；教師記功則預設第6條第2項第2款第9目。畫面上的「點」留白表示不適用，教師 CSV 匯出時仍填 999 / 99，沿用 WebHR 既有匯入慣例。公務人員則不自動推定適用法規與條點項款目，CSV 預設全部留空，但保留教示條款 1。

教示條款依人員類別自動判斷：職稱含「教師」或現支官職等是薪額制 → 2 教育人員；其餘（護理師、幹事等職員）→ 1 公務人員。

獎懲類別預設 A02 工作績優，出現比賽、研習、研究等關鍵字會自動換成 A07 / A06 / A05。每一筆都能自己改。

## 已知限制

**職稱沿革會自動從批核軌跡建立。** 人員基本資料表只有現職，查不到「113 學年度當時的教導主任是誰」。但公文後半的批核軌跡會寫出簽核者的職稱和日期：

```
…高雄市湖內區三侯國民小學教導主任 侯進昇(2025.09.23 08:12)
…高雄市湖內區三侯國民小學教導主任 楊崇甫：114/12/19 14:09:30
```

把一批公文的簽核紀錄彙整起來，就看得出職務什麼時候交接：

```
教導主任： 侯進昇（114/09–114/10） → 楊崇甫（114/12–115/07）
```

所以 PDF 要**一次全部上傳**，某份公文的「時任是誰」答案往往藏在另一份的簽核紀錄裡。上傳新批次時所有公文會重新比對一次。

公文主旨提到的年度比發文年度早，就是在敘過去的事，候選人會把在任較早的排前面。例如喜閱網那份主旨寫「113學年度」、發文於 114 年，「教導主任」就會指向侯進昇而不是現職的楊崇甫。

**只有職稱時，優先對應的是「現職」。** 「教導主任，教學組長，訓導組長各嘉獎1次」會用現在的職稱去名冊找人。比對分三層：

1. 職稱完整寫在名冊裡 —— 教學組長、訓導組長
2. 職稱對不上就看單位 —— 公文寫「教導主任」，名冊職稱是「教師兼教務主任」但單位是「教導處」，靠單位就能和總務主任區分開。職稱和單位欄位要**分開比**：職稱寫明單位的優先，都沒有才看單位欄位。混在一起比會讓「幼稚園主任但單位掛在教務處」的人也符合「教務林主任」
3. 都對不上才放寬成只看職務別，列出所有候選人讓你挑
4. 再補上批核軌跡查到的歷任者，下拉會標出各自的在任期間

職稱旁邊如果已經寫了姓名，那個職稱是在描述那個人，不會另外算成一個受獎人 —— 例如「時任資訊執秘為:吳孟謙老師」，講的就是吳孟謙，不會把現任的資訊執秘也拉進來。

這類推定一律標示提醒，不預設核章。批核軌跡查不到、名冊上也沒有的人（例如已離職者），依「名冊上沒有的人不敘獎」原則不會出現，該筆不核章即可。

**表格式擬辦仍會保守提醒。** 程式已能判斷「獎度在前、姓名在後」的表格方向；像學生健檢公文可正確配成郭喜淑嘉獎二次、李雅玲與林怡慈嘉獎一次。若同一人因兼任兩項工作在表格重複出現，系統會保留兩筆；只有表格錯位或無法辨識兩筆的不同事由時，才會標黃並取消預設核章。

**公文與擬辦的頁面順序不固定。** 無論公文在前、擬辦在後，或擬辦先列印、公文接在後面，程式都會分別找出主旨與擬辦再配對。若同一個 PDF 混入兩組以上的公文或擬辦，系統會以檔名和主旨的相似度選擇案件並標黃提醒，避免誤抓到前一份公文。

**無法合理判斷時會列出建議頁碼。** 例如擬辦只有名額、看不出受獎人、獎度只寫在來文，或 PDF 內混有兩組案件，畫面會提示應優先查看第幾頁的擬辦、敘獎名單或獎度說明；程式不會為了湊出結果而硬猜姓名。

**擬辦沒列名單時才讀批核意見。** 擷取範圍只取「批核意見：」之後的內容，簽核者的姓名寫在那一行之前，不會被撈進比對，所以校長、人事主任不會被誤認成受獎人。

姓名在名冊上完全相符、獎度也明寫在同一段時，可靠度等同從擬辦讀到的，會自動核章，並在該列標示「取自批核意見」讓你知道資料來源。姓名只是疑似或推定的仍要人工確認。

**Big5 缺字。** 像「蒓」這種字不在 Big5 字集裡，匯出時會提示。WebHR 的姓名欄位是從個人基本資料表2現職檔帶出來的，CSV 只要身分證號正確通常沒問題，但也可以改用 UTF-8 匯出。

**校長由人員名冊控制。** 上傳基本資料前先排除校長；系統只會產生名冊內的人員，不另外提供排除開關。

**代理教師會特別標示。** 教師成績考核辦法適用對象是編制內專任合格教師，代理教師是否適用請自行確認。
